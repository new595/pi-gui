# GUI 个人维护与框架选择评估

日期：2026-10-04。用户明确的目标是固定 GUI 产品版本，CLI 和公共扩展仍按需更新；本次进一步评估是否需要从头自写 GUI 或更换框架。

## 结论与状态

用户最终决定（2026-10-04）：继续维护现有 GUI，不从头重写或更换框架。CLI 和公共扩展仍按需更新；GUI 保留当前个人分支和功能，维护聚焦必要兼容和安全修复。本次确认只更新维护文档与工作约定，没有实施补丁修复、扩展隔离、运行时升级或配置变更。下述其他路线仅保留为比较资料。

现阶段建议继续维护现有个人分支，先处理 GUI 扩展隔离与运行时安全维护，不建议仅因最近扩展更新覆盖补丁就从头重写。可以不跟进官方 GUI 的全部功能发布，但现有二进制不适合永久原样冻结。

若将来确实需要新客户端，优先缩小功能范围、复用现有界面和协议类型，并评估通过 Pi 官方 RPC 调用 CLI。框架选择应由桌面功能、部署方式和实测资源需求决定。本报告是评估与建议，尚未实施扩展隔离、RPC 后端、Electron 升级或框架迁移。

## 长期维护的实际边界

GUI 可以保持现有功能和个人分支，按需吸收安全、协议和兼容修复。Electron 官方日程列明 37 系列于 2026-01-15 结束支持，37.10.3 页面也提示 end-of-support。因此运行时更新应纳入自维护范围；这不等于已经证明当前应用存在某个可利用漏洞，也不意味着框架本身必须更换。

GUI 扩展隔离的建议结构：保留真实 agentDir 和认证、模型、会话路径；GUI 使用自己的固定扩展清单与完整依赖副本；只在资源加载层覆盖 packages/extensions。GUI 的扩展开关写入独立清单，后台子代理也绑定同一套兼容 SDK 和扩展树。现有 SettingsManager.fromStorage、resourceLoaderOptions 可以作为实现入口，但没有现成单开关完成全部隔离，不能只复制入口 TS/JS 文件。

公共 CLI 扩展继续按需更新，经过 GUI 验收的版本才进入 GUI 清单。共享配置与会话、模型 provider 协议仍需兼容检查。源码重建应保留锁文件，并验证原生终端、代理、认证、扩展交互与安装包；尚未评估跨 Electron 主版本升级的实际修复量。

## 更换框架的工程判断

现有源码已经分开 React renderer、browser-safe contracts、session-driver/catalogs 与 Node Pi SDK driver。大部分界面和类型有复用基础，但 Electron 的 preload/IPC、窗口归属、node-pty 与 WebContents 通信、OAuth 浏览器与对话框桥接、通知/剪贴板/文件、扩展资产协议与权限需要迁移。已有分层支持渐进改造，没有从零重写全部代码的必要。

| 路线 | 适合的目标 | 新增或继续承担的维护 |
| --- | --- | --- |
| 现有 Electron 个人分支 | 保留当前功能，控制改动范围 | 扩展隔离、宿主 UI 适配、SDK/provider 兼容、受支持运行时与打包验证 |
| 浏览器界面 + 本地服务 + Pi RPC | 自用、简化桌面功能，先验证小客户端 | 本地服务生命周期、来源和访问控制、RPC 事件/取消/断线恢复、版本兼容 |
| Tauri + 现有 React + Node sidecar 或 Pi RPC | 明确需要独立桌面壳，并重视运行时部署方式 | Rust 壳与 IPC、Node/CLI 子进程、桌面能力迁移、完整桌面验收 |

Tauri 在 Windows 使用 WebView2；采用 Evergreen 分发可以由运行时更新机制维护浏览器内核。它不会替代 Node Pi SDK 和 npm 扩展的运行环境，也不会自动解决主/后台代理或终端 custom UI 兼容。若保留直接 SDK 集成，通常需要独立 Node 后端；若改用 RPC，仍需维护协议适配与子进程。

当前没有安装体积、内存、启动速度或持续运行性能的路线对比实测，不能承诺换框架会更快、更省内存或更稳定。

## 如果未来做新客户端

先保留工作区/会话列表、流式聊天、模型切换、停止任务及必要的文件/图片输入。代理执行、工具运行、认证和会话管理尽量委托 Pi CLI。先完成一轮正常对话、工具调用、取消、会话恢复和扩展提问验证，再决定是否迁移更多桌面功能。

Pi 1.0.2 官方 RPC 文档确认它可作为长驻子进程，用 stdin/stdout JSONL 接受命令并发送事件。客户端必须处理请求关联、退出、取消和流式事件；不能把命令接收成功当作模型执行成功。RPC 支持 select/confirm/input/editor 等 UI 请求，但 custom() 返回 undefined，终端专用扩展仍需支持的回退或继续在 CLI 使用。RPC 不是全部 TUI 功能的通用图形化转换器，未来协议变化也不能保证零维护。

只有出现明确的 Electron 特有阻塞、实测资源瓶颈、浏览器访问需求，或者用户决定明显缩减现有功能时，才建议启动迁移原型。若主要目标是降低维护投入，应优先裁功能和收紧兼容范围。
